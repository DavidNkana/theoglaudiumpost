# Source Articles Navigation Fix Documentation

## Issue Description

Users were unable to navigate to the Source Articles page in the admin panel. When clicking on the Source Articles link in the sidebar, the page would not load, and the following errors were observed in the console:

```

Unchecked runtime.lastError: A listener indicated an asynchronous response by returning true, but the message channel closed before a response was received
```

Despite the user being authenticated and having the admin role, they were unable to access the Source Articles page.

## Root Cause Analysis

After investigating the codebase, we identified the following:

1. The Source Articles link in the sidebar was correctly implemented as an anchor tag with a click handler that calls the `navigateTo` function with the path '/admin/source-articles'.
2. The router configuration for the Source Articles route was properly defined with the correct path, component, and meta information.
3. The Source Articles component was properly implemented with an `onMounted` hook that initializes modals and calls `fetchSourceArticles()`.
4. The `fetchSourceArticles` function calls `getSourceArticlesFromAllTasks()` from the articles service.
5. The `getSourceArticlesFromAllTasks` function was making a GET request to "/api/v1/sourceArticles/all".
6. The API_BASE_URL was defined as "http://192.168.0.246:9011/laudium/api/v1/".

The root cause of the issue was that the `getSourceArticlesFromAllTasks` function was using "/api/v1/sourceArticles/all" as the endpoint path, but the API_BASE_URL already included "/laudium/api/v1/", resulting in a duplicate "/api/v1/" in the URL. This was causing a 404 error or other API issues, preventing the Source Articles page from loading.

## Changes Made

We updated the `getSourceArticlesFromAllTasks` function in `src/services/articles.js` to use "sourceArticles/all" instead of "/api/v1/sourceArticles/all" to avoid the duplicate prefix:

```javascript
// Before
export const getSourceArticlesFromAllTasks = () => {
  return api.get("/api/v1/sourceArticles/all");
};

// After
export const getSourceArticlesFromAllTasks = () => {
  return api.get("sourceArticles/all");
};
```

This change ensures that the API call uses the correct URL without the duplicate "/api/v1/" prefix, allowing the Source Articles page to load properly.

The test will output information about the API call and whether it was successful. If the test passes, it means the fix is working correctly.

## Guidance for Future Maintenance

When working with API endpoints in this project, keep the following in mind:

1. The API_BASE_URL is defined in `src/config/api.js` and already includes "/laudium/api/v1/".
2. When making API calls, use relative paths without the "/api/v1/" prefix to avoid duplication.
3. For example, use "sourceArticles/all" instead of "/api/v1/sourceArticles/all".
4. If you need to add a new API endpoint, follow the same pattern to ensure consistency.

If similar issues occur in the future, check the API endpoint paths to ensure they don't include duplicate prefixes.

## Additional Notes

The "Unchecked runtime.lastError" messages in the console are not directly related to this issue. They are typically generated by Chrome extensions or Chrome APIs and can be safely ignored.

The "Tried to use the 'fill' option without the 'Filler' plugin enabled" warning is related to a third-party library and is also not directly related to this issue.

## Conclusion

The issue was caused by a duplicate "/api/v1/" prefix in the API endpoint path, which was fixed by updating the `getSourceArticlesFromAllTasks` function to use the correct path. This fix allows users to navigate to the Source Articles page in the admin panel.
